# aiffected — project guide

An interactive editorial explainer about how Generative AI could reshape the
economy: grow GDP while raising unemployment, and what that means for jobs,
income, meaning and society. Plus a set of shareable single-idea "briefs" with
polls and live comments.

- **Stack:** Vite + React 19, hand-rolled SVG visuals (no chart libs). Vercel
  serverless functions (`/api`) + MongoDB for polls/comments.
- **Live:** https://aiffected.seibtribe.us (Vercel; `base` is `/` on Vercel,
  `/aiffected/` elsewhere — see `vite.config.js`).
- **Design language:** dark theme; Fraunces (serif headings), Inter (body),
  JetBrains Mono (labels); teal accent `#5eead4`. Tokens live at the top of
  `src/styles.css` (`:root`). One global stylesheet.
- **Author:** George Seib (`src/author.js`, byline links to LinkedIn).

## Build & scripts

```bash
npm run dev      # vite dev (NO /api — use `vercel dev` to exercise the backend)
npm run build    # prebuild (gen-briefs) -> vite build (multi-page)
npm run briefs   # regenerate b/<slug>/index.html + vercel.json redirects from briefs.js
npm run og       # regenerate public/og/*.png (needs Playwright + a running preview)
```

`npm run build` runs `scripts/gen-briefs.mjs` first (prebuild), so brief pages
and redirects always match `briefs.js`.

## Layout of the main page (`src/App.jsx`)

`wave` state (1 cognition / 2 robotics / 3 autonomy) lives in App and is shared
by Simulator + Sectors. Order: Nav → Hero → Mechanism → Waves → Simulator →
Sectors → Alarmist → Society → Meaning → VoicesSpectrum → Closing.

- `model.js` — the illustrative economic model: per-wave config, `compute()`,
  presets, levers, plus a wave-3 "human leverage" metric. Stylized, not a
  forecast.
- `Simulator.jsx` — wave toggle + levers + animated SVG charts (from
  `Charts.jsx`: LineChart, SplitBar, Gauge, Counter, Reveal).
- `Sectors.jsx` — per-wave task-exposure bars (cognitive vs physical).
- `Alarmist.jsx` — "is this alarmism?" reader question + optimist/skeptic columns.
- `Society.jsx` → `SocialContract.jsx` — "draft your social contract": dilemma
  board, a Market↔Collective × Work↔Post-work compass, archetypes, and the
  "human ledger" (what a job pays out beyond a wage).
- `Meaning.jsx` — "Now what?": concentric rings of contribution (self→world).

## The Chorus (real thinkers) — `voices.js`, `Voice.jsx`, `VoicesContext.jsx`

20 real thinkers as inline `❝ Surname` chips placed at the claim they bear on.
Hover = quote preview; click = modal with full quote, role, context, source link.

- **Accuracy rule (important):** a quote shown in quotation marks must be
  verbatim. Summaries are marked `verbatim: false` on the voice — they render
  WITHOUT quote marks, get a "paraphrase" badge, and a "summary, not a verbatim
  quote" note. Don't put constructed text in quotes next to a real name.
- **Counter-views:** a voice may have `counter: '<id>'`. Chips then show a `⇄`
  icon; hover gives the counterpoint's quote + source link, click opens its
  modal. The modal also has a "⇄ The counter-case" button. Pairs are the bold
  doom claims vs credible optimists (amodei↔autor, frey↔oecd, harari↔bessen,
  piketty↔mccloskey, bregman↔cass, etc.). Only add a counter where a real,
  named rebuttal exists.
- `Term.jsx` + `glossary.js` — glossed jargon (dotted underline + tooltip).
  `Glossed` auto-wraps the first occurrence of any glossary term in plain-string
  copy (used in brief dek/question and Alarmist bullets). Add a term once in
  `glossary.js` and it glosses everywhere those helpers render.

## Briefs (8 shareable single-concept pages)

Source of truth: **`src/briefs.js`** (one object per brief). Fields: `slug`,
`eyebrow`, `title` (array of strings / `{em,tone}`), `dek`, `kind`, `voice`,
`deep` (section id to deep-link to), `cta`, `question` (the "⇄ Crying wolf?"
pushback), `poll`, `seeds`, `ogTitle`, `ogDesc`.

- `Brief.jsx` renders one brief; `kind` selects the visual (paradox, ledger,
  rings, decoupling, sectors, split, gauge, debate) — all reuse site primitives.
  The CTA button reveals George's note on hover; below it sit the poll and the
  conversation. `?og=1` renders a clean 1200×630 card (no poll/comments/CTA),
  used to screenshot the share image.
- **Why static HTML per brief:** social scrapers don't run JS, so each brief is
  its own `b/<slug>/index.html` with baked OG/Twitter meta (generated by
  `scripts/gen-briefs.mjs`; wired as Vite multi-page inputs in `vite.config.js`).
- **OG images:** `public/og/<slug>.png`, generated by `scripts/gen-og.mjs`
  (Playwright screenshots of `?og=1`) and **committed** — Vercel's build can't
  run a browser. Regenerate with `npm run og` after a running `npm run preview`.
- **Short links:** `/brief1…/brief8` and `/<slug>` redirect to `/b/<slug>/`,
  generated into `vercel.json` by `gen-briefs.mjs`. Numbering follows list order.
- **Share hub:** `/share/` (`share/index.html` → `src/share.jsx` → `ShareHub.jsx`)
  lists the full page + all briefs with thumbnail, short link, copy-link button,
  and the brief's poll question as a teaser.
- **Absolute URLs:** `SITE_URL` (default `https://aiffected.seibtribe.us`) is used
  for og:image/og:url/canonical in `gen-briefs.mjs` and `index.html`. Change it
  if the domain changes, then `npm run briefs`.

## Polls & comments (backend) — `/api`, MongoDB

- `api/_db.js` — cached Mongo client (`getDb()`), `body()` helper.
- `api/poll.js` — GET `?brief=` returns `{counts}`; POST `{brief, option}` does
  `$inc` on `counts.<option>`. Option ids are validated as safe slugs and defined
  per brief (so a brief's options can be anything). Collection `polls`, one doc
  per brief: `{ _id: <slug>, counts: { <optionId>: n } }`.
- `api/comments.js` — GET `?brief=` returns approved; POST inserts `pending`
  (length-capped, IP-hashed with `IP_SALT`, light 4/min rate guard). Collection
  `comments`: `{ brief, name, text, color, status, createdAt, ipHash }`.
- `api/moderate.js` — admin-only (header `x-admin-token` === `ADMIN_TOKEN`):
  GET pending/approved/rejected, POST `{id, action: approve|reject|delete}`.

Frontend:
- `BriefPoll.jsx` — two poll types. Default `choice` (bars). `type:'slider'`
  renders a draggable scale over discrete stops; each stop has a numeric `value`
  (or `null` for "Never"), and results show the **average of the dated stops**
  plus the % who chose the null stop, with a per-stop distribution. (Brief 5 uses
  this: "How long before AI could do your job?")
  - **Gotcha:** the displayed total sums only the *current* options' counts, so
    changing a poll's option ids orphans old votes (ignored) rather than
    inflating the total. Keep `id`s stable once voting starts; labels are free to
    reword. To reset, delete the brief's doc from the `polls` collection.
- `BriefComments.jsx` — a "danmaku" band where approved comments drift across in
  quiet monochrome cards (even-spaced so they never overlap; hover pauses). Click
  opens a modal with the full comment; ←/→ flip through, Esc closes. A textarea +
  optional first name + Post submits a `pending` comment. Per-brief `seeds` keep
  the band alive before real comments exist. Pre-moderation: nothing shows until
  approved at `/admin`.
- `/admin/` (`admin/index.html` → `src/admin.jsx` → `AdminModerate.jsx`) — paste
  `ADMIN_TOKEN`, approve/reject/delete from the queue. `noindex`.

### Required env vars (Vercel project → Settings → Env, or `.env.local` for `vercel dev`)
- `MONGODB_URI` (required) — connection string. **Never commit / never paste in chat.**
- `MONGODB_DB` (optional, default `aiffected`)
- `ADMIN_TOKEN` (required for `/admin`)
- `IP_SALT` (optional) — salt for hashing commenter IPs
See `.env.example`. `.env*` is gitignored.

## Gotchas / conventions
- The conversation is a `<section>`, so it inherits the global `section` rule
  (padding/max-width/centering). `.convo` resets those to align with the body
  column — don't remove that.
- Briefs in `?og=1` mode must stay free of poll/comments/CTA so the card image
  is clean; gate those on `!og` in `Brief.jsx`.
- `npm run dev` has no `/api`; the poll/comments degrade gracefully (seeds +
  optimistic UI). Use `vercel dev` to actually hit Mongo locally.
- Visuals are hand-rolled SVG; match existing patterns in `Charts.jsx`.
- Work happens on branch `claude/genai-economy-visualizer-w9frlc` (the repo's
  default branch). Commit + push when changes are complete.
